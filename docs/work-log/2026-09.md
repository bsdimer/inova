## 2026-09-16 — Deploy pipeline: self-healing JWT key ownership

**Changed:** `provision.sh` now re-asserts ownership and mode on
`secrets/jwt-private.pem` on every run instead of only when it creates the key.
auth-service reads the key as uid 1000 (`node`), so root-owned root-group
permissions make it exit with `EACCES` on boot — and because the key is read
once at module init, the breakage only appears the next time the container is
recreated, which can be hours after whatever changed the ownership (here, a
recursive `chown` during a manual config sync).

**Verified:** The first CI-driven deploy failed exactly this way and failed
closed: `deploy.sh` refused to finish, and the health gate reported the
unhealthy service rather than declaring success. After correcting ownership on
the host, auth-service, core-api, the SPA, JWKS and a seeded login all answer
through the proxy again.

**Remains:** Nothing for this fix. The demo-seed credentials on the public test
URL still need rotating, and off-box backups are still unaddressed.

## 2026-09-16 — Deploy pipeline: nginx config mount safety

**Changed:** The deploy workflow replaced `/opt/inova/nginx` wholesale on every
run, but the nginx container bind-mounts `nginx/conf.d`. Removing that directory
leaves the running container attached to the old, unlinked inode, which it sees
as empty — so `nginx -t` passed, the reload succeeded, and nginx came back with
no `listen` directives at all and the site unreachable. The sync now clears the
directory's contents instead of the directory, `deploy.sh` compares the config
the container sees with the one on disk and recreates the container instead of
reloading when they differ, and `proxy-common.conf` moved into `conf.d` as
`proxy-common.inc` so the stack no longer bind-mounts a single file (a file
mount pins an inode the same way).

**Verified:** The new layout passes `nginx -t` in a throwaway container against
a self-signed certificate, with `.inc` correctly outside `conf.d/*.conf`
auto-inclusion. On the host, recreating nginx restored service: the portal,
both health endpoints, JWKS and a seeded login all answer, and the stack is
running the CI-built GHCR images.

**Remains:** Demo-seed credentials on the public URL still need rotating, and
off-box backups are still unaddressed.
