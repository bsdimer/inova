## 2026-09-16 — Brand token alignment: warning colour, radius scale, seed tenant name

**Changed:** Rebuilding the admin UI in Figma from its own source surfaced three
places where the admin had drifted from `brands/inova/brand.json`, which the
mobile app mirrors.

1. The palette had no semantic attention colour, so the `suspended` status badge
   used raw Tailwind `amber-500/600` — the only colour in the admin not coming
   from the brand. Added `warning` (`#A45F0B` light, `#E8A33C` dark) to
   `brand.json` colours and both themes, to `brandThemeSchema` in

   stripping it, and to the mobile token mirror. `StatusBadge` now uses it.

   `brand.json` and mobile use 12/18/28/999. Overrode `--radius-xl/2xl/3xl` in
   the admin `@theme` so both clients round on the same scale, and replaced the
   login card's one-off `rounded-[2rem]` with `rounded-3xl`.

briefly renamed here and then reverted: `implementation-plan.md` describes the
pilot as launching under the platform's own brand *acting as the first tenant*,

would have hidden the hard case from the test data. The ambiguity is answered in
the UI instead — explicit scope labels, an audit banner and a single Return to
platform action, designed on the M1 Figma page.

## 2026-09-16 — Test environment and deployment pipeline

**Changed:** Added a container deployment for the shared test host
(204.168.180.167): one parameterised Dockerfile for both NestJS services and
one for the admin SPA, a compose stack (Postgres, Redis, auth-service,
core-api, admin, nginx) in `infra/deploy/`, and an nginx front proxy that
terminates TLS for `portal.whitenova.tech`, serves the admin build at `/`, and
proxies `/api/` and `/auth/` to the two services with the prefix stripped —
path routing, so one certificate, one DNS record and no CORS. Added idempotent
`provision.sh` (Docker, 2 GB swap, ufw, generated credentials and JWT signing
key, renewal timer), `obtain-cert.sh` (initial HTTP-01 issuance),
`renew-certs.sh` on a twice-daily systemd timer that reloads nginx only after
an actual renewal, and `deploy.sh` (pull, migrate, app-role password sync,
rollout, health gate, proxy verification). Added
`.github/workflows/deploy.yml`: builds amd64 images to GHCR and deploys over
SSH, gated on a green CI run on `main`. Postgres and Redis publish no ports;
Docker's iptables rules bypass ufw, so they are unreachable rather than merely
firewalled.

**Verified:** All three images built for `linux/amd64` and smoke-tested locally
(migrations applied from the image, JWKS served from the mounted key, both
health endpoints and the SPA fallback answering, container healthchecks
reporting healthy). Bootstrapped the host with the same scripts CI runs:
certificate issued (expires 2026-12-15), `https://portal.whitenova.tech/`
returns the admin app, `/api/v1/health` and `/auth/v1/health` return `ok`, JWKS
resolves, HTTP redirects to HTTPS, an unknown Host gets 444, and a seeded login
returns a signed JWT end to end. `certbot renew --dry-run` succeeds over the
webroot with nginx running, so renewal is proven rather than assumed. `pnpm
verify` passed in full.

**Remains:** The pipeline itself has not run yet — `workflow_run` only fires
from `main`, so the first CI-driven deploy happens when this branch merges;
the host currently runs side-loaded `:bootstrap` images. The seed ran on the
test host, so the documented demo credentials are live on a public URL and
should be changed or the seed dropped before the box is shared. Backups
(`pg_dump` to off-box storage) and the mobile app's API base URL are not part
of this change.
